# Navigation Architecture — `lib/navigation/`

## Overview

This directory contains the **modular navigation configuration** for the ERP platform, implementing a **4-Layer Domain-Driven Hierarchy**:

```
Domain (The Why)
  └── Capability (The What)
        └── Feature Group (The How)
              └── Screen (The Do)
```

## Architecture

### Type System (`types/navigation.d.ts`)

```typescript
Domain → Capability[] → FeatureGroup[] → NavScreen[]
```

Each `NavScreen` includes:
- `id` — unique identifier
- `title` — display title (i18n-ready)
- `icon` — icon from the registry  
- `href` — route path (follows `/domain/capability/feature` pattern)
- `permissions` — RBAC access control array
- `module` — backward-compatible module key

### Central Hub (`index.ts`)

The hub provides **two APIs**:

#### New Domain-Driven API (Recommended)
```typescript
import { allDomains, getDomain, getCapability, getAllScreens, searchScreens } from '@/lib/navigation';
```

#### Legacy Backward-Compatible API
```typescript
import { navigationGroups, getAllNavigationLinks, getNavigationGroup, isNavigationLink } from '@/lib/navigation';
```

The legacy API is auto-generated by transforming `Domain[]` → `NavigationGroup[]` so existing sidebar, search, and top bar components continue to work without modification.

## Design Decisions

1. **Separation of Concerns**: Each domain is a self-contained config file — edit `supply-chain.config.ts` without touching finance.
2. **i18n Ready**: All `title` fields can be swapped with translation keys.
3. **RBAC Ready**: `permissions[]` on every screen enables role-based visibility filtering.
4. **URL Consistency**: Every `href` follows `/domain/capability/feature` ensuring user orientation.
5. **Backward Compatibility**: Legacy `NavigationGroup[]` is derived, not duplicated — single source of truth.

## Migration Path

The old `lib/navigation-config.ts` remains as a reference. Consumer files should gradually migrate their imports:

```diff
- import { navigationGroups } from '@/lib/navigation-config';
+ import { navigationGroups } from '@/lib/navigation';
```

No functional changes needed — the legacy API signature is identical.
