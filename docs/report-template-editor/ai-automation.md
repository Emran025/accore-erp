# AI & Automation Roadmap

The Report Template Editor is designed not just for manual editing, but as a foundational system for **AI-Driven Automated Reporting**.

## AI Command Readiness

By structuring templates with strictly defined `{{keys}}` and validated HTML, the system is prepared for LLM (Large Language Model) integration.

### Proposed AI Workflows:

#### 1. "Generate Template via Prompt"
Users will be able to provide a natural language prompt like:
> "Create an official warning letter for late attendance with fields for date, employee name, and number of late hours."

The AI agent can then:
- Call the `TemplateEditor` with a pre-filled `body_html` generated by the AI.
- Automatically map the relevant `approvedKeys` based on context.

#### 2. "Intelligent Auto-Correction"
If a user tries to save a template with broken layout or overlapping styles, the AI can:
- Analyze the `body_html`.
- Recommend a "Prettified" version.
- Suggest missing CSS fixes for RTL/LTR compatibility.

#### 3. "Automated Reporting via AI Agent"
An AI agent can trigger report generation by:
- Identifying the correct template for a given task (e.g., "End of Year Review").
- Gathering the necessary data from the ERP database.
- Performing the "Key Injection" programmatically.
- Exporting the final document without human intervention.

## Architectural Enablers

To support these workflows, the component already provides:
- **Machine-Readable Schemas**: The `TemplateField[]` array provides clear "Type" and "Description" for every data point, which is essential for LLM context.
- **Strict Validation**: Prevents the AI from accidentally generating insecure code (e.g., `<script>` injection).
- **Categorical Mocking**: Allows the AI to test its own generated templates against realistic data before presenting them to the user.

## Future Specifications

To further enhance AI integration, the following features are planned:
- **Template Metadata API**: A centralized endpoint to fetch all available keys for an AI brain.
- **CSS Variable Standardization**: Ensuring all AI-generated reports follow the same `--report-primary` variables.
- **Dynamic Key Discovery**: Allowing the AI to "discover" new keys based on database schema changes.

---

> [!NOTE]
> The current structure of `{{key}}` syntax is chosen for its simplicity and wide recognition by LLMs, making it the most efficient "hand-off" format between AI and the ERP Engine.
